## Why

Every consumer renders its own copy of the tester and releaser workflows, so a shared-logic fix (the `environment: crates-io` omission proved the cost) must be rolled out consumer by consumer through `copier update`. Python-project-common already demonstrates the alternative: thin local callers invoking versioned cross-repo reusable workflows, so one reviewed change to the shared file fixes the fleet.

## What Changes

- Add `.github/workflows/xrepo--tester.yaml` at the repository root (cross-repo `uses:` requires a repo-root path, so it cannot live under `template/`). It is template-owned infrastructure versioned with the same git tags as the template. Inputs: `platforms` (JSON array of {os, cpu, runner, target} objects, bound at each call site to the initializer's `platforms` output), `cargo-profile` (validated string, `dev` or `release` — Cargo's own profile names, not `debug` — where a leading step rejects anything else), `has-library` (boolean, deciding whether doctest steps run). No secrets in, no publishing, no tag mutation.
- The reusable workflow chains lint into build into test, fanning out as a build matrix over the platforms, so every gate compiles and lints natively. Lint runs clippy, rustfmt `--check`, and linecheck on every profile — native per-platform execution, because `cfg`-gated code makes clippy results platform-dependent and no single-runner shortcut survives that. Build compiles `--all-targets`; test runs nextest plus doctests (when `has-library`) with per-profile flags spelled out explicitly — no pre-commit invocation in CI, no pasted `--profile` flag.
- `tester.yaml` becomes thin callers: `initialize`, one `xrepo--tester.yaml` call with `cargo-profile: dev`, one with `cargo-profile: release` in parallel, plus the consumer `custom` job and a single-runner `hygiene` job. The pre-commit/hook story changes in exactly one way: hooks stay the local fast path (lint plus unit tests via pre-commit; release twins via pre-push) but CI runs explicit steps instead of invoking the hook runner; a copiertv assertion keeps the CI step commands and the hook entry commands byte-identical so neither side drifts silently.
- The needs graph has no conditional jobs: lint always runs on both profiles, build needs lint, test needs build, and the custom job needs only `initialize` — no mandatory gate job is ever present-but-skipped. Failure or cancellation upstream can still skip downstream jobs; the `final-gate` umbrella (`if: always()`, failing unless every needed result is `success`) exists precisely to turn those skips into inspected red. The only conditional element in CI is the *rendered* `custom` job, which exists or does not exist; it is never present-but-skipped. `final-gate` needs all gate jobs including custom when rendered and fails closed on any non-success.
- Releaser release-gates call `xrepo--tester.yaml` with `cargo-profile: release`; a local per-platform `package` job runs unconditionally (custom off or on, dry-run, publication off); `publish-crates-io` and `build-binaries` wait on whole-`platforms` release success plus `package` plus `custom-release` when rendered, keeping tag/dry-run/publication predicates and credential protections; `publish-github` follows transitively via `build-binaries`, unconditionally whenever the publisher exists.
- A single-runner `hygiene` job runs the file-hygiene hook IDs (large-file, filename-case-conflict, merge-conflict-marker, symlink, VCS-permalink, destroyed-symlink, private-key, mixed-line-ending, JSON, TOML, YAML checks, plus end-of-file and trailing-whitespace fixers) with one `pre-commit run <id>` invocation per ID taken from the template's own pre-commit configuration (rendered config path, pre-commit stage, all files, pinned pre-commit tool, failing on any invocation): the one sanctioned exception to "no pre-commit in CI" wherever that rule is stated, since the alternative is reimplementing file checks as shell.
- Least privilege is explicit everywhere: every cross-repo `uses:` call and the shared callee run at `contents: read` or less with no secrets; local `package` and `hygiene` jobs are least-privilege with credential-less non-pushing checkouts; write and OIDC stay confined to the existing local publishers; the tester triggers on `pull_request`, never `pull_request_target`; `platforms` entries are validated against the pinned supported runner/target mapping before fan-out and never interpolated into shell source.

- A single non-matrix `final-gate` job that branch protection targets: `needs` on all gate jobs including custom when rendered, `if: always()`, fails unless every needed result is `success`. Per-platform jobs stay legible individually; the umbrella gives one stable context instead of per-platform names.
- A `custom-release` job calling consumer-owned `local--releaser.yaml` under the same `enable_custom_ci` answer (one switch for the whole custom story, not one per lane); `publish-crates-io` and `build-binaries` wait on it alongside the release gates. Both job-level `uses:` calls declare explicit `contents: read`, pass no secrets, and pass no `has-library`. Custom jobs declare `platforms` and `cargo-profile` — one fewer than the shared tester, deliberately: the shared workflow is generic and must be told the crate shape, while the custom author knows their own crate and encodes library-ness directly, so there is nothing to pass — and receive the whole platform array per call, fanning out internally exactly like the shared workflow; the template stubs are generated when absent and fail loudly with implementation instructions. Existing no-input custom files are preserved byte-identical by `_skip_if_exists` and MUST be migrated deliberately (add the declared inputs), because passing undeclared inputs fails workflow resolution — there is no silent fallback. Consumer-owned files that read `needs.initialize.outputs.cells` need the same hand migration: Copier rewrites rendered callers, not arbitrary consumer-owned readers.
- Versioning: every change to a cross-repo file cuts an immutable `@gha-X.Y` tag; the floating major (e.g. `@gha-1`) advances with it and is what consumers pin by default. Breaking changes start the next major. This mirrors the practiced python-project-common discipline. The initial tag ships before any consumer renders a caller referencing it. Before any floating-major move, the fixture callers on template-owned `fixture/promotion-*` branches — each a real rendered crate at its checkout root, calling the literal hosted ref `emcd/rust-project-common/.github/workflows/xrepo--tester.yaml@<candidate-sha>` with the candidate SHA pinned — must report their expected verdicts: green on the lib and bin branches over dev and release, gate-step failure on the red branch, validation-step failure on a bogus profile; tag creation, update, and deletion is restricted to the operator-owned promotion process, published immutable tags never move, promotion rechecks evidence freshness (exact SHA, caller revisions, tag/main eligibility), and recovery rolls back only to retained immutable pins with operator authorization and fixture-green evidence; first tag and all moves remain operator-owned.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `quality-gates`: CI gates execute through versioned cross-repo reusable workflows with explicit per-profile steps instead of rendered inline steps or a pre-commit stage invocation; the custom-job contract gains input parity with the shared tester.

## Impact

- `.github/workflows/xrepo--tester.yaml` (new, repo-root; the only file whose logic is shared).
- `template/.github/workflows/tester.yaml.jinja` (thin callers plus `custom`, `hygiene`, and `final-gate` jobs).
- `template/.github/workflows/common-initializer.yaml.jinja` (`cells` output renamed to `platforms`) plus the caller bindings in the tester/releaser jinja.
- `template/.github/workflows/releaser.yaml.jinja` (release-gates becomes a caller).
- Fixture caller branches `fixture/promotion-lib`, `fixture/promotion-bin`, `fixture/promotion-red` (real rendered crates at root, each calling the pinned candidate SHA; template-owned, created once with operator approval, never rendered to consumers).
- Documentation in the applying guide on versioning (`@gha-X.Y` per change, floating major default, bump major on breakage) and on the custom-input contract including the no-input migration.
- Consumers: re-pin replaces rendered gate bodies with callers (reconcile custom jobs into `local--tester.yaml` at the same time); lint coverage widens to every cell natively and release gates run on every PR, which is an intended behavior change from this proposal.
